# Frontmatter and folder rules

Reference for the `custom-agent-review` skill. Open at Step 2 of `SKILL.md`. Source of every rule: `docs/custom-agent-authoring-guide.md`.

## How to judge each check

**B1.** Run the inventory from Step 1. Zero or two agent files means B1, and the review stops at Step 1. Claude Code skips a file whose `---` is not on line 1, so report the exact line. Quote any value containing a colon followed by a space.

**B2.** Extract `name` from every `*.agent.md` under `.agents/`, lowercase it, and list duplicates. A duplicate makes agent selection ambiguous, so a collision is a blocker. A frontmatter `name` that differs from the folder or file stem is B2 as well: Copilot identifies an agent by its file name and Claude Code by its `name` field, so one agent then has two identifiers.

**B4.** Three forms all fail: no `tools` line, `tools: ["*"]`, and a `#tools:` comment that stands in for a decision. An omitted line inherits every tool in Claude Code and enables every tool in Copilot. `tools: []` disables all tools and passes B4, but it fails B10 unless the agent targets only Copilot and says so.

**B8.** Frontmatter descriptions are injected into the context of the agent that chooses or delegates, so angle brackets are a prompt-injection vector, as for skills. Search the values of `description`, `argument-hint` and `metadata`, the text a harness loads to choose or describe the agent. Square brackets (`[repo-url]`, a bracketed `tools` list) and angle brackets in the body or in YAML comments do not fail B8. A placeholder such as `<repo-url>` in `argument-hint` does; suggest `REPO-URL` or `[repo-url]`.

**B9.** A permission mode that skips confirmation is the agent equivalent of pre-approved tools, and it is functionally unattended execution. Fail B9 when a pre-approving `permissionMode` or auto-approving hook is set, or the body instructs the agent to push, deploy, delete or otherwise act irreversibly without asking. An agent that genuinely needs unattended execution must name the narrow, low-risk task it implements, and fails B9 if it names none. Mark B9 `n/a` when the agent has no irreversible action. Do not guess the risk of the systems it touches: ask the author when the scope is unclear.

**B10.** Claude Code refuses to launch a subagent whose `tools` list resolves to nothing, with the error `would be spawned with zero tools`, so every prompt to the agent aborts. An agent in this repository targets Claude Code and Copilot unless its PR description names a single harness. Read the list and fail B10 when no entry is a Claude-style built-in (`Read`, `Edit`, `Write`, `Grep`, `Glob`, `Bash`, `TodoWrite`) or an `mcp__` name. The typical failure is a Copilot-only list such as `[read, edit, search, execute, todo, server/*]` or `search/listDirectory`. Read the list; do not run the agent. Mark B10 `n/a` for an agent that targets only Copilot and says so.

**W1-W3.** A description names what the agent does, when to use it with phrases a user types, and when not to. Compare with these:

```yaml
# PASSES W1-W3
description: "Use when auditing one repository for dependency hygiene, started with a repo URL. Do not use for batch audits (use org-audit)."
# FAILS W1 and W2: no trigger words, no boundary
description: Reviews a pull request acting as a senior developer.
```

**W4.** Documented fields: `name`, `description`, `tools`, `disallowedTools`, `model`, `argument-hint`, `metadata`, plus the harness-specific `handoffs`, `user-invocable`, `disable-model-invocation`, `target` (Copilot) and `permissionMode`, `maxTurns`, `skills`, `mcpServers`, `hooks`, `memory`, `effort`, `isolation` (Claude Code). Claude Code ignores any other key without a message, so a typo has no effect and no error.

**W5.** Claude-style built-ins resolve in both (Copilot documents them as aliases), and each harness skips the MCP form meant for the other. So the portable form is one comma-separated line with each MCP server in both forms. Fail W5 for a bracketed or multi-line list (not shown in the Claude Code documentation and not tested), for an MCP server named in one form only (Copilot ignores `mcp__` names, so the agent loses the tool there), for a server name that differs from the configured one, and for a capability named only by a lowercase alias or Copilot ID. An extra entry that resolves in one harness only is fine. Mark W5 `n/a` when the agent targets a single harness and the names fit it.

**W6.** A reviewer, planner or auditor gets read, search and read-only commands, and no `Edit`, `Write` or write MCP tool. A shell is justified when the PR description names the commands the job needs. A shell also requires `risk: high` and a named second reviewer (verdict cap and FAIL rule: `SKILL.md`, Step 5). A wildcard over an MCP server is justified when the PR description says why the named tools are not enough.

**W7 and W18-W20.** These mirror W5, W6 and W16 of `agent-skill-review`, so a missing `metadata` block is a set of warnings (PASS WITH WARNINGS), never a blocker. A person's name in `owner` fails W7. `last-reviewed: 2026-10-21` without quotes fails W18, because YAML parsers read it as a date and the map holds strings, and so does a date in the future or older than one quarter. A `source-repository` with a username, a `.git` suffix, a branch or a file path fails W19. W20 fails on a version that is not semver, a status outside the three values, or any risk other than `low` or `high` (reject `medium`). Report an absent key as a failure of its check. Copilot ignores `metadata` in IDEs and Claude Code ignores it without a message, so do not fail an agent for carrying it, and raise an advisory when a body instruction depends on a `metadata` value.

**A1.** Reads `.vscode/settings.json` and the root `README.md` of the reviewed repository. Mark `n/a` outside a repository that keeps an agent catalog.

**A2.** A deprecated agent keeps its description edited first (`DEPRECATED, use X instead.`) because the description controls selection.
